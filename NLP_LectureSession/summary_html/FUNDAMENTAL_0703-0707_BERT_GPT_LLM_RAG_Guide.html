개요 · 큰 그림

세 개의 강의(BERT / GPT / LLM & RAG)를 하나의 이야기로 읽는 지도

딥러닝의 대부분은 학습을 “정답을 맞추는 과정”으로 본다. 하지만 언어에는 정해진 정답이 드물다. 단어의 의미는 그 자체가 아니라 다른 단어들과의 관계 속에서 생긴다. 그래서 사전학습 언어모델은 “무엇을 맞출까(task)”가 아니라 “언어의 구조를 파라미터에 내재화하는 것”으로 목표를 옮긴다. 이 관점의 전환이 BERT·GPT를 관통하는 핵심이다.

모든 모델의 뿌리는 Transformer다. Transformer는 크게 인코더 블록과 디코더 블록으로 이뤄지는데, 여기서 두 갈래가 나온다. 인코더만 쌓으면 문맥을 양방향으로 보는 BERT가 되고, 디코더만 쌓으면 앞에서 뒤로 한 방향으로 생성하는 GPT가 된다.

이 문서를 읽는 순서

01~02에서 Attention과 두 블록으로 트랜스포머를 복습하고, 03~05에서 BERT·GPT·정렬(RLHF)을, 06~08에서 LLM의 한계와 이를 넘으려는 RAG·경량화를 다룬다. 앞 장의 개념이 뒷장에서 계속 재사용되니 순서대로 보는 걸 권한다.

01

Attention 다시 보기

BERT도 GPT도 결국 이 연산의 반복이다 — Q·K·V로 문맥을 섞는 법

Attention의 아이디어는 단순하다. 어떤 단어를 표현할 때, 다른 단어들의 정보를 얼마나 가져올지 가중치를 매겨 섞는다. 이 가중치를 계산하기 위해 각 토큰을 세 가지 역할의 벡터로 투영한다.

Q (Query) · 지금 무엇을 찾는가 K (Key) · 나는 어떤 정보를 가졌는가 V (Value) · 실제로 전달할 정보

실제로 Q·K·V는 입력 임베딩 $E$에 각각의 학습 가중치를 곱해서 만든다. $Q = E W_Q,\; K = E W_K,\; V = E W_V$. 즉 같은 입력에서 세 갈래로 나온 표현이다.

Scaled Dot-Product Attention

Query와 Key의 내적(유사도)으로 점수를 내고, 차원 크기로 나눠 스케일을 맞춘 뒤, softmax로 확률처럼 정규화한다. 그 가중치로 Value를 가중합한 것이 출력이다.

핵심 수식

$$\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V$$

왜 $\sqrt{d_k}$로 나눌까

차원 $d_k$가 커지면 내적값의 분산도 함께 커진다. 값이 너무 크면 softmax가 한쪽으로 극단적으로 쏠려(거의 0 또는 1) 기울기가 소실된다. $\sqrt{d_k}$로 나눠 점수의 스케일을 안정시켜야 학습이 매끄럽다.

아래 위젯은 위 수식을 실제로 계산한다. 세 토큰 “나는 / 밥을 / 먹었다” 각각에 대해 Q·K·V가 주어져 있고(실제로는 $E W_Q$ 등으로 얻는 값), Query 토큰을 바꾸면 점수 → 스케일 → softmax → 출력이 단계별로 다시 계산된다.

Scaled Dot-Product Attention 계산기Query 토큰을 골라 한 단계씩 따라가기
Query 토큰:
# PyTorch로 쓰면 딱 이만큼
import torch, math

def scaled_dot_product_attention(Q, K, V, mask=None):
    d_k = Q.size(-1)
    scores = Q @ K.transpose(-2, -1) / math.sqrt(d_k)   # (…, Lq, Lk)
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float('-inf'))
    weights = torch.softmax(scores, dim=-1)             # 행 합 = 1
    return weights @ V, weights                         # 출력, 어텐션 분포

Self-Attention Q=K=V의 출처가 같음

Self-Attention은 Q·K·V를 모두 같은 문장에서 뽑는다. 즉 문장이 자기 자신을 보며 단어 간 관계를 학습한다. 순서는 Q-K 유사도로 스코어를 내고 → softmax로 Attention Distribution을 만들고 → V를 가중합해 Attention Vector를 얻는 3단계다.

Multi-head Attention 여러 관점으로 동시에

단일 Attention 하나로는 다양한 문맥(문법 관계, 지시 관계, 의미 관계…)을 한꺼번에 담기 어렵다. 그래서 벡터를 $h$개의 head로 쪼개 각자 독립적으로 Attention을 수행하고, 결과를 concat한 뒤 linear로 다시 섞어 의미를 통합한다.

직관

차원 $d_{model}$을 $h$개로 나눠 각 head가 $d_k = d_{model}/h$ 차원에서 서로 다른 “관심사”를 학습한다. 하나의 큰 Attention보다, 여러 개의 작은 Attention이 표현의 다양성을 만든다.

Encoder & Decoder Block

BERT를 만드는 블록과 GPT를 만드는 블록, 무엇이 같고 무엇이 다른가

Masked Self-Attention 미래를 가린다

생성 모델은 왼쪽에서 오른쪽으로 한 토큰씩 만든다. 그런데 학습할 때 정답(뒤쪽 토큰)을 미리 보면 반칙이다. 그래서 각 위치가 자기 자신과 이전 위치까지만 볼 수 있도록, softmax 직전에 미래 위치의 점수를 $-\infty$로 채운다(마스킹). 그러면 softmax 후 그 자리의 가중치가 0이 된다.

# 상삼각(미래)을 True로 만들어 -inf 마스킹
L = 5
# 대각선 위쪽(미래 위치)만 1 → 마스킹 대상
causal = torch.triu(torch.ones(L, L), diagonal=1).bool()
scores = scores.masked_fill(causal, float('-inf'))   # 미래 차단
weights = torch.softmax(scores, dim=-1)              # 각 행은 과거에만 분포

아래 위젯에서 모드를 Encoder(양방향) ↔ Decoder(마스킹)로 바꿔 보면, 디코더에서 우상단(미래)이 통째로 가려지는 걸 바로 확인할 수 있다. 셀의 숫자는 실제로 softmax를 계산한 어텐션 가중치이고, 각 행의 합은 항상 1이다.

03

BERT

Bidirectional Encoder Representations from Transformers — 인코더로 언어를 이해하기

BERT는 Transformer의 인코더 구조를 쌓은 모델이다. 앞서 본 “task 중심”에서 벗어나, 단어의 문맥적 의미 자체를 파라미터에 새기는 두 가지 사전학습 과제를 쓴다: MLM과 NSP.

MLM — Masked Language Modeling 단어의 문맥적 의미

문장의 일부 단어를 [MASK]로 가리고, 남은 양방향 문맥으로 가려진 단어를 맞힌다. 앞뒤를 모두 보기 때문에 GPT의 단방향 예측보다 풍부한 문맥 표현을 얻는다.

예시

Some people are running
→ Some [MASK] are there   →  모델이 people 예측

강의엔 안 나온 디테일: 15%와 80/10/10

BERT는 토큰의 15%를 예측 대상으로 고른 뒤, 그중 80%는 [MASK]로, 10%는 임의의 다른 단어로, 10%는 원래 단어 그대로 둔다. 이유는 학습–추론 불일치 완화다. 파인튜닝·추론 때는 [MASK] 토큰이 없는데, 학습을 100% [MASK]로만 하면 모델이 “[MASK] 자리만 신경 쓰는” 편향을 갖게 된다. 그래서 일부러 마스크가 아닌 경우도 섞는다.

NSP — Next Sentence Prediction 문장 간 관계

두 문장 A, B를 주고 B가 A 다음에 실제로 이어지는 문장인지(IsNext / NotNext) 이진 분류한다. 문장 사이의 의미 관계를 학습해 QA·자연어 추론 같은 문장 쌍 과제에 대비한다.

  • 학습 데이터의 50%는 진짜 이어지는 쌍(IsNext), 나머지 50%는 무작위로 붙인 쌍(NotNext)
  • 판별은 문장 맨 앞 [CLS] 토큰의 최종 표현을 써서 수행한다

Embeddings — 세 임베딩의 합

BERT의 입력은 세 임베딩을 더해서 만든다. Transformer 자체는 순서 개념이 없으므로 위치 정보를 따로 넣어야 하고, 문장 A/B를 구분하는 세그먼트 정보도 필요하다.

Fine-Tuning — 하나의 사전학습, 여러 과제

사전학습된 BERT 위에 가벼운 출력 헤드만 얹어 각 과제(MNLI 추론, NER 개체명, SQuAD QA…)에 맞게 미세조정한다. 예컨대 SQuAD에서는 정답이 문단의 어디서 시작하고 끝나는지 Start/End Span을 예측한다. 무거운 표현 학습은 한 번만 하고, 과제별로는 살짝만 손대는 것이 사전학습–파인튜닝 패러다임의 핵심이다.

04

GPT

Generative Pre-trained Transformer — 디코더로 언어를 생성하기

GPT는 Transformer의 디코더 구조를 쓰고, 핵심은 Masked Attention이다. 각 위치가 이전 토큰들만 보며 다음 단어를 예측하도록 학습한다(autoregressive language modeling).

GPT의 디코더에는 없는 것

원래 Transformer 디코더에는 인코더 출력을 참조하는 인코더–디코더 어텐션(cross-attention)이 있다. 하지만 GPT는 인코더가 아예 없다. 그래서 cross-attention도 없고, Masked Self-Attention + FFN 블록만 쌓는다. 02장 디코더 그림에서 점선으로 표시한 그 층이 GPT엔 빠진 셈이다.

GPT가 가져온 변화

In-Context Learning · 예시만 보고 즉석 적응 LLM · 규모의 법칙 생성형 AI · 새 콘텐츠 창작

In-Context Learning은 파라미터를 업데이트하지 않고도, 프롬프트 안에 몇 개의 예시(few-shot)만 넣으면 모델이 그 자리에서 패턴을 파악해 문제를 푸는 능력이다. 규모가 커질수록 이 능력이 창발적으로 강해졌고, 이것이 LLM과 생성형 AI 시대를 열었다.

05

InstructGPT & RLHF

“그럴듯한 텍스트 생성”에서 “지시를 따르는 모델”로

InstructGPT는 GPT-3를 사용자의 지시(Instruction)를 더 잘 따르도록 파인튜닝한 버전이다. Hugging Face에서 배포되는 모델의 -instruct, -chat, -rlhf 태그가 이런 정렬(alignment)을 거쳤음을 나타낸다. 정렬은 보통 SFT → 보상 모델 → PPO의 3단계로 진행된다.

1단계 · SFT (Supervised Fine-Tuning)

기존 모델은 “텍스트를 그럴듯하게 생성”하는 것이 목표다. SFT는 instruction–response 데이터로 “지시사항을 수행”하는 과제를 지도학습으로 가르친다.

SFT의 한계

사람이 직접 만든 예시로 데이터셋을 구성하다 보니 ① 데이터 수가 부족하고 ② 모든 상황을 커버하지 못하며 ③ 무엇보다 이 답이 좋은지 나쁜지 평가할 기준이 없다. “맞는 답”은 알려줄 수 있어도 “더 나은 답”은 가르치기 어렵다.

2~3단계 · Reward Model & PPO

이 “좋고 나쁨”의 기준을 사람 대신 매겨 주는 것이 보상(Reward) 모델이다. 사람이 여러 응답에 매긴 선호(랭킹)를 학습해, 임의의 응답에 점수를 준다. 그 뒤 PPO(Proximal Policy Optimization)로 보상이 높은 출력의 확률을 키운다. 결과적으로 ① 더 자연스러운 문장 구조, ② 더 정확한 정보, ③ 유해 정보 생성 억제를 얻는다. 단, 모든 경우에 PPO가 필요한 건 아니다.

PPO 학습 순서
  1. 입력 $x$에 대해 응답 후보 $y$를 여러 개 샘플링
  2. 각 $(x, y)$ 쌍을 보상 모델로 reward 계산
  3. KL penalty로 원래 policy와 너무 크게 벌어지지 않도록 제약
  4. reward가 높았던 출력의 확률은 ↑, 낮은 출력의 확률은 ↓ 방향으로 업데이트
헷갈리기 쉬운 지점: KL penalty ≠ ratio clipping

강의 자료는 “KL penalty로 reward 값을 제한(Clipping)”이라 묶어 설명하는데, 엄밀히는 두 가지 서로 다른 장치다. ⑴ KL penalty는 RL 정책이 SFT 기준 모델에서 너무 멀어지지 않게 붙이는 벌점항이다(보상 해킹 방지). ⑵ PPO의 이름이 된 clipping은 목적함수에서 확률비(ratio) $\frac{\pi_\theta}{\pi_{old}}$를 일정 범위로 잘라 한 번의 업데이트가 과격해지지 않게 하는 장치다. 둘 다 “안정화”라는 목적은 같지만 대상이 다르다.

06

LLM의 구조적 한계

잘 만든 LLM에도 구조에서 비롯되는 여섯 가지 한계가 있다 — 그리고 각각의 극복 시도

LLM은 강력하지만, 그 강력함이 곧 만능은 아니다. 아래 한계들은 프롬프트를 잘 쓴다고 사라지지 않는, 모델 구조 자체에서 나오는 제약이다. RAG를 비롯한 여러 기법이 이 한계들을 겨냥한다.

1확률적 언어 모델

LLM은 다음 단어의 확률 분포를 예측한다. 사실 판단(factual reasoning)보다 언어적 일관성과 패턴 재현에 강하다. 그럴듯하지만 틀린 말(환각)이 나오는 근본 이유다.

07

RAG

Retrieval-Augmented Generation — 모델 밖의 지식을 끌어와 답한다

표기 바로잡기

강의 슬라이드 제목의 Retrueval은 Retrieval의 오타다. 정식 명칭은 Retrieval-Augmented Generation이다.

RAG는 LLM이 답을 만들기 전에 관련 문서를 먼저 검색해 프롬프트에 붙여 주는 방식이다. 앞 장의 한계 1(사실성)과 2(지식 고정)를 직접 겨냥한다. 모델을 다시 학습하지 않고도, 검색된 최신·근거 문서를 바탕으로 답하게 만든다.

RAG의 4단계
  1. 프롬프트 입력 — 사용자의 질문
  2. 관련 문서 검색 — 문서 저장소(주로 벡터 DB)에서 의미상 가까운 문서를 찾음
  3. 프롬프트 + 문서 — 검색 결과를 질문과 함께 모델 입력으로 결합
  4. 답변 생성 — 그 문맥을 근거로 응답 생성

덕분에 모델을 재훈련하지 않고도 최신 지식을 반영하고, 출처가 있는 답을 만들 수 있어 환각을 줄인다. 한계 3(context window)과도 맞물리는데, 필요한 문서만 골라 넣으므로 제한된 창을 효율적으로 쓴다.

08

모델 경량화

너무 커진 LLM을 실전에서 굴리기 위한 네 가지 압축 전략

상용 LLM은 최저 크기가 70B 수준이다. 이 몸집은 곧 리소스·Latency·비용 문제로 이어진다. 그래서 성능을 최대한 지키며 크기를 줄이는 경량화가 필수다. 대표 기법은 Pruning · Knowledge Distillation · LoRA · Quantization이다.

표기 바로잡기

슬라이드의 RoLA는 LoRA(Low-Rank Adaptation)의 오타다. 이름 그대로 저(low)-랭크(rank) 근사를 이용한다.

Pruning — 가지치기

중요도가 낮은 연결(시냅스)이나 뉴런을 잘라내 네트워크를 성기게 만든다. 대상 단위에 따라 뉴런 / 레이어 / 개별 가중치 수준으로 나뉜다. 잘라도 성능 손실이 작다면 그만큼 연산량과 메모리를 아낀다.

Knowledge Distillation — 지식 증류

큰 teacher 모델의 지식을 작은 student 모델로 옮긴다.

  • Response-based Distillation — teacher의 확률 분포 자체를 모방하도록 student를 학습(soft label)
  • Data Distillation — teacher가 생성한 합성 데이터로 student를 학습

LoRA — Low-Rank Approximation

가중치 행렬 $M$을 더 낮은 차원의 두 행렬 곱으로 근사한다. $M\;(m\times n)$을 랭크 $k$로 근사하면 $M \approx L_k R_k^{\top}$가 되고, 여기서 $L_k$는 $m\times k$, $R_k^{\top}$는 $k\times n$이다($k \ll \min(m,n)$).

아래 계산기로 실제 절감 효과를 확인해 보자. LoRA는 특히 파인튜닝에서 위력적이다 — 원본 가중치 $W$는 얼려 두고 저랭크 행렬 $L, R$만 학습하면, 갱신할 파라미터가 극적으로 줄어든다.

Quantization — 양자화

일반적으로 가중치는 32비트 부동소수점(FP32)으로 저장한다. 이를 8비트 정수(INT8)로 바꾸면 파라미터 수는 그대로인 채 저장 크기를 ¼로 줄인다. 핵심 아이디어는 실수 범위 $[\min, \max]$를 정수 격자에 매핑하는 것이다.

# FP32 → INT8 비대칭 양자화의 뼈대
levels = 2**8 - 1                     # 255
scale  = (x.max() - x.min()) / levels
q      = ((x - x.min()) / scale).round().clip(0, levels)  # 정수로
x_hat  = q * scale + x.min()          # 역양자화(복원값) — 약간의 오차 발생

아래 위젯은 위 식을 실제로 수행한다. 비트 수를 낮출수록 저장은 작아지지만 복원 오차(회색↔주황 막대의 차이)가 커지는 정확도–크기 트레이드오프가 눈에 보인다.

같은 Transformer에서 인코더 → BERT(이해)와 디코더 → GPT(생성)가 갈라지고, GPT는 RLHF로 지시를 따르는 LLM이 되며, 그 구조적 한계는 RAG(지식 보강)와 경량화(효율)로 메워진다.

자주 헷갈리는 포인트 3가지

① BERT의 마스킹 ≠ GPT의 마스킹. BERT는 단어를 [MASK]로 가려 복원(MLM)하고, GPT는 미래 위치를 $-\infty$로 가려 다음 토큰 예측(causal mask)한다. 목적이 다르다.

② GPT는 디코더지만 cross-attention이 없다. 인코더가 없으니 참조할 대상도 없다. Masked Self-Attention + FFN만 쌓는다.

③ PPO의 KL penalty와 clipping은 별개. KL penalty는 기준 모델에서 멀어지지 않게, clipping은 업데이트 폭이 과격해지지 않게 하는 서로 다른 안정화 장치다.
