NLP란 무엇인가

0629 · slide 2–4

NLP(Natural Language Processing, 자연어 처리)는 자연어를 컴퓨터가 이해하고 처리하는 과정 전체를 가리킨다. 반드시 AI에 한정된 개념은 아니다 — 규칙 기반 문법 검사기나 통계 기반 검색 엔진도 NLP다. 다만 오늘날 NLP라고 말하면 일반적으로 딥러닝 기반의 처리를 상정한다.

여기서 자연어(Natural Language)란 자연상에서 발생한 사람의 말이다. 한국어, 영어, 수어처럼 누가 설계하지 않았는데도 쓰이며 진화해 온 언어를 말한다. 반대편에는 인공어(Artificial Language)가 있다 — Python 같은 프로그래밍 언어, 에스페란토처럼 명시적 규칙으로 설계된 언어다. 인공어는 문법이 완전하고 모호함이 없지만, 자연어는 그렇지 않다. 그리고 바로 그 "그렇지 않음"이 NLP를 어렵게 만든다.

⬤ 더 넓은 정의

NLP는 "언어 형태(representation)로 표현 가능한 모든 의미를 모델링하고 변환하는 문제"다. 텍스트 → 텍스트뿐 아니라, 이미지 → 설명문(캡셔닝), 음성 → 텍스트, 요구사항 → 코드처럼 한쪽이 언어이기만 하면 모두 이 문제 틀 안에 들어온다. "번역기 만들기"가 아니라 "의미의 변환"이 NLP의 본질이라는 관점이다.

자연어의 세 가지 특징

인공어와 달리 자연어는 다음 세 성질 때문에 단순한 규칙으로는 처리할 수 없다. 딥러닝이 NLP의 표준이 된 이유가 여기에 있다.

특징 1맥락 의존성

같은 문장이라도 맥락에 따라 의미가 변한다. 단어 하나만 봐서는 뜻을 확정할 수 없다.

"배가 크다" — 과일 배? 타는 배? 사람 배? 앞뒤 문장이 있어야만 결정된다.
특징 2불완전성

실제 언어는 규범(맞춤법·문법)을 충족하지 않는 경우가 많다. 그래도 사람은 이해한다.

"ㅋㅋ 낼 학교 감?" — 문법적으로 불완전하지만 의미 전달에는 문제가 없다.
특징 3다양성

언어, 방언, 은어, 신조어 등 형식과 표현이 무한히 다양하고 계속 새로 생겨난다.

"밥 먹었어?" = "밥 뭇나?" = "식사하셨어요?" — 같은 의미, 다른 표현.
■ 핵심 정리
  • NLP = 자연어를 컴퓨터가 이해·처리하는 과정. AI 전용 개념은 아니지만 현재는 딥러닝을 상정한다.
  • 넓게 보면 언어로 표현 가능한 모든 의미의 모델링과 변환 문제다.
  • 자연어는 맥락 의존성 · 불완전성 · 다양성 때문에 규칙 기반으로는 한계가 명확하다.
02

NLP Task와 생성 패러다임

0629 · slide 5–9

NLP는 오랫동안 문제를 잘게 쪼개서 풀어 왔다. task마다 전용 모델, 전용 데이터셋, 전용 평가 방법이 따로 있었다. 대표적인 task를 하나의 예문에 적용해 보면 각각이 무엇을 뽑아내는지 한눈에 보인다.

Task무엇을 하는가예문: "손흥민은 어제 런던에서 골을 넣었다"
품사 태깅
POS Tagging		각 단어에 품사를 붙인다손흥민/고유명사 은/조사 어제/부사 …
개체명 인식
NER		사람·장소·기관 등 고유 개체를 찾는다손흥민=PERSON, 런던=LOCATION
구문 분석
Parsing		문장의 문법 구조(트리)를 밝힌다[손흥민은 [어제 [런던에서 [골을 넣었다]]]]
질의 응답
QA		질문에 대한 답을 찾는다Q: 누가 골을 넣었나? → A: 손흥민
번역
Machine Translation		다른 언어로 옮긴다Son scored a goal in London yesterday.
요약
Summarization		핵심만 남기고 줄인다손흥민, 런던서 득점.

Transformer 이후의 변화 — 모든 것이 생성 문제로

Transformer 등장 이후 판이 바뀌었다. 첫째, task마다 다르던 모델 구조가 동일한 구조(Transformer)로 수렴했다. 둘째, 위의 서로 다른 문제들이 전부 텍스트 생성 문제 — 즉 다음 토큰 예측(Next Token Prediction) 하나로 통일됐다.

기존 방식생성 방식 (프롬프트 → 다음 토큰 예측)
감성 분류 전용 모델이 [0.9, 0.1] 출력"이 리뷰의 감성은?" → 모델이 "긍정"이라는 토큰을 생성
번역 전용 seq2seq 모델"다음을 영어로 번역: 안녕" → "Hello" 토큰들을 순서대로 생성
NER 전용 태거가 BIO 태그 출력"인명을 모두 추출해줘" → "손흥민"을 생성

자연어는 왜 생성 문제인가

이 통일이 억지가 아니라 자연스러운 귀결인 이유가 있다.

  • 언어 자체가 생성 과정이다. 말은 단어–단어–단어로 이어지며 만들어진다. 다음 단어를 잘 고르는 능력이 곧 언어 능력이다.
  • 의미가 분포적으로 표현된다. 단어의 의미는 사전 정의가 아니라 "어떤 맥락에서 어떤 단어와 함께 나타나는가"라는 분포로 학습된다. 다음 토큰 예측은 이 분포를 직접 학습하는 방법이다.
  • task들이 사실 동일 문제군이다. 분류·추출·번역·요약 모두 "입력 조건에 맞는 텍스트를 출력하라"의 특수 케이스다.
  • NLG는 NLU를 전제한다. 좋은 요약을 생성(NLG)하려면 원문을 이해(NLU)해야만 한다. 생성을 잘하도록 학습하면 이해가 내부에 딸려 온다.

그러나 — 생성으로 처리했을 때의 문제점

모든 것을 생성으로 풀 수 있다는 것이 모든 것을 생성으로 풀어야 한다는 뜻은 아니다. 생성 방식에는 뚜렷한 비용이 따른다.

문제 1출력 구조 불안정

"JSON으로만 답해"라고 해도 형식이 깨질 수 있다. 분류기는 무조건 5개 클래스 중 하나를 내지만, 생성 모델은 계약을 보장하지 않는다.

문제 2정밀도가 아닌 "그럴듯함"

생성 모델은 가장 그럴듯한 다음 토큰을 고르도록 학습됐다. 사실이 아니어도 유창하게 말할 수 있다(환각).

문제 3제약 조건 적용의 어려움

"정확히 10자", "이 단어는 반드시 포함" 같은 하드 제약을 확률적 생성 과정에 강제하기 어렵다.

문제 4효율성 및 비용

스팸 여부 하나 판단하는 데 거대 모델의 자기회귀 생성을 돌리는 것은 작은 분류기 대비 수백 배 비쌀 수 있다.

문제 5평가 가능성

분류는 정답과 비교하면 끝이지만, 생성은 정답이 여러 개라 채점 자체가 어렵다. (→ 10장 평가지표에서 다시 다룬다)

그래서 task를 이해해야 한다

"어차피 LLM이 다 해주는데 왜 옛날 task들을 배우나?"에 대한 답이다.

  1. 생성 모델도 각 task를 내부적으로 수행한다(내재화). 요약을 생성할 때 모델 내부에서는 개체 인식·구문 이해에 해당하는 계산이 암묵적으로 일어난다.
  2. 잘하는지 못하는지의 판단은 task 단위로 이뤄진다. "이 모델은 한국어 NER이 약하다"처럼, 진단과 비교의 단위는 여전히 task다.
  3. 실제 시스템은 완전한 end-to-end가 드물다. 검색 + 분류기 + 생성 모델을 조합하는 것이 현실의 파이프라인이다.
  4. task마다 요구사항이 다르다. 법률 검색은 정밀도, 안전 필터는 재현율이 생명이다. 요구사항을 정의하려면 task의 언어를 알아야 한다.
■ 핵심 정리
  • 전통 NLP는 task별 전용 모델의 세계였다 — POS, NER, Parsing, QA, 번역, 요약.
  • Transformer 이후 구조는 하나로, 문제는 "다음 토큰 예측"으로 통일됐다.
  • 생성 통일에는 근거가 있지만(언어 = 생성 과정, 분포적 의미), 구조 불안정 · 환각 · 제약 · 비용 · 평가라는 비용이 따른다.
  • 따라서 task 단위의 이해는 생성 시대에도 진단·설계·평가의 기본 언어다.
03

NLP 파이프라인

0629 · slide 10–16

문장은 그대로 모델에 들어가지 못한다. 모델은 텐서(숫자 배열)만 계산할 수 있기 때문이다. 그래서 모든 NLP 시스템은 "문장 → 숫자 → 계산 → 다시 사람의 언어"라는 변환의 연쇄로 이뤄진다. 먼저 일반적인 인공지능 파이프라인부터 보자.

  1. 데이터 수집 — 원천 데이터를 모은다.
  2. 데이터 정제 — 노이즈·중복·오류를 제거한다.
  3. 표현 변환 — 모델이 다룰 수 있는 형태(숫자)로 바꾼다.
  4. 모델 입력 — 배치 단위로 모델에 넣는다.
  5. 텐서 계산 — 모델이 순전파 연산을 수행한다.
  6. 출력 후 디코딩 — 계산 결과를 사람이 쓸 수 있는 형태로 되돌린다.

이 일반 파이프라인을 NLP에 특화하면 다음 5단계가 된다. 3단계(표현 변환)가 NLP에서는 Tokenizing–Encoding–Vectorization 세 단계로 세분화되는 것이 핵심이다.

fig 3-1 · NLP 파이프라인 — Tokenizing → Encoding → Vectorization → Inference → Decoding

1단계 — Tokenizing

문장을 컴퓨터가 처리할 수 있는 작은 단위(토큰)로 분리하는 과정이다. 단위 선택이 곧 트레이드오프다: 단어 단위는 의미가 또렷하지만 어휘 수가 폭발하고 처음 보는 단어(OOV)에 취약하다. 문자 단위는 어휘가 작지만 의미가 흩어지고 시퀀스가 길어진다. 그래서 현재는 메모리를 절약하면서도 의미를 보존하는 subword 단위가 표준이다 — "먹었다"를 "먹" + "었다"로 쪼개는 식이다. 15장에서 다룬 BPE·SentencePiece가 바로 이 subword 분리 알고리즘이다.

2단계 — Encoding

각 토큰을 정수 ID로 매핑한다. 이 매핑표가 어휘 사전(vocabulary)이다. 정수 ID를 무한정 만들 수는 없으므로 어떤 토큰을 사전에 등록할지 결정해야 한다 — 보통 학습 코퍼스의 빈도순으로 상위 N개를 등록하고, 등록되지 않은 토큰은 특수 토큰 <unk>(unknown)로 처리한다. vocab을 키우면 표현이 정밀해지지만 임베딩 행렬과 출력층이 커진다.

3단계 — Vectorization

정수 ID 자체는 순서 이상의 의미를 갖지 못한다. ID 7("먹는다")이 ID 5("학교에")보다 크다는 사실에는 아무 의미가 없다. 그래서 각 ID를 벡터 공간 위의 점으로 분포시켜, 크기와 방향이 의미를 담는 데이터로 변환한다. 이것이 임베딩(embedding)이다. 학습이 진행되면 단어 간의 의미적·패턴적 관계가 벡터 공간의 기하 구조로 반영된다 — 비슷한 맥락에서 쓰이는 단어들은 가까운 곳에 모인다(12장 워드 임베딩에서 확인한 그 성질이다).

4단계 — Inference

모델(RNN, Transformer 등)이 임베딩 벡터 시퀀스를 받아 문맥적 특징을 계산한다. 같은 "배"라도 앞뒤 단어에 따라 다른 표현이 되는 것은 이 단계 덕분이다. 참고로 실무에서는 임베딩 변환 자체를 모델 내부에 포함시키는 것이 일반적이다 — PyTorch에서 nn.Embedding이 모델의 첫 번째 층으로 들어가고, 임베딩 행렬도 역전파로 함께 학습된다. 즉 3단계와 4단계의 경계는 개념적 구분이지 물리적 구분이 아니다.

5단계 — Decoding

추론 결과(숫자)를 사람이 해석할 수 있는 형태로 되돌리는 과정이다. 분류라면 각 class별 확률로, 생성이라면 확률 분포에서 고른 ID를 다시 자연어 단어로 변환한다. Encoding의 역방향이라고 생각하면 된다.

INTERACTIVE 파이프라인 체험 — 문장이 텐서가 되기까지 widget 01
예문:
STEP 1 · TOKENIZING — 어절 단위 분리
STEP 2 · ENCODING — vocab 조회 (미등록 토큰은 <unk>=1)
STEP 3 · VECTORIZATION — ID → 4차원 임베딩 벡터
토큰화는 실제 어절 분리, 인코딩은 14개짜리 장난감 vocab에서의 실제 조회다. 임베딩 벡터는 ID로부터 결정적으로 생성한 고정 난수 — 실제 모델에서는 이 값들이 학습으로 갱신되는 파라미터라는 점만 다르다. 이후는 Inference(모델 연산)와 Decoding(사람의 언어로 복원)이 이어진다.
■ 핵심 정리
  • NLP 파이프라인: Tokenizing → Encoding → Vectorization → Inference → Decoding.
  • Tokenizing은 현재 subword가 표준 — 메모리 절약과 의미 보존의 절충.
  • 정수 ID는 순서 이상의 의미가 없으므로 벡터 공간에 분포시켜(임베딩) 의미 관계를 담는다.
  • 임베딩은 보통 모델 내부에 포함되어 함께 학습된다 (nn.Embedding).

모델 출력 설계

0629 · slide 17–19

초심자는 "어떤 모델을 쓸까"부터 고민하지만, 설계의 올바른 순서는 정반대다. 무엇을 출력해야 하는지(Y)를 먼저 확정하고, 그 출력 형태가 손실 함수를 결정하고, 마지막에야 모델 구조를 고른다. 출력에서 거꾸로 설계하는 것이다.

출력값의 두 기본형

유형 1Classification — Discrete Label

출력이 이산적인 라벨이다. 유한한 선택지 중 하나를 고른다.

스팸 / 정상 · 긍정 / 중립 / 부정 · vocab 중 다음 토큰 1개
유형 2Regression — Continuous Value

출력이 연속적인 실수 값이다. 크기 자체가 의미를 가진다.

평점 예측 4.2점 · 내일 기온 23.7°C · 문장 유사도 0.87

설계 예시 — Summarization

"요약"이라는 task를 위의 순서대로 밀어 보면 이렇게 전개된다.

  1. task 정의 — 긴 원문을 짧은 요약문으로 변환한다.
  2. Y 설계 — Y는 요약문. 요구사항: 원문의 고유 명사가 보존되어야 하고, 길이가 원문보다 짧아야 한다.
  3. 모델 출력 설계 — 요약문 전체를 한 번에 낼 수 없으니 다음 단어 예측을 반복하는 구조로 분해한다. 매 스텝의 출력은 vocab 전체에 대한 확률 분포다.
  4. 손실 함수 설계 — 매 스텝이 "vocab 중 정답 단어 고르기"라는 분류 문제이므로 스텝별 cross-entropy를 쓴다.
  5. 모델 설계 — 이 출력 구조를 낼 수 있는 모델: seq2seq(16장), Transformer(18장).
⬤ 관점의 전환

"요약문 출력"처럼 복잡해 보이는 Y도 결국 "각 단어별 확률 분포"라는 단순한 출력의 반복으로 환원된다. 어떤 거창한 생성 task든 매 순간의 출력은 분류(vocab 위의 discrete label 선택)라는 사실 — 이것이 다음 섹션 Next Token Prediction의 출발점이다.

■ 핵심 정리
  • 설계는 출력(Y)에서 거꾸로: task 정의 → Y 설계 → 모델 출력 설계 → 손실 함수 설계 → 모델 설계.
  • 출력의 기본형은 둘: Classification(이산 라벨)과 Regression(연속 값).
  • 요약 같은 생성 task도 "다음 단어 확률 분포"의 반복으로 분해된다.
05

RNN과 Next Token Prediction

0629 · slide 20–26

앞 섹션에서 "생성 = 다음 토큰 예측의 반복"이라는 결론에 도달했다. 그렇다면 이전 단어들을 기억하면서 다음 단어를 예측하는 구조가 필요하다. 그 최초의 답이 RNN(Recurrent Neural Network, 순환 신경망)이다.

RNN의 구조 — 하나의 셀을 계속 재사용한다

RNN의 핵심은 같은 셀(파라미터)을 시간축을 따라 반복 적용한다는 것이다. 매 시점 t에서 셀은 두 개를 입력받는다: 현재 입력 xt와 직전 시점의 은닉 상태 ht−1. 이 둘을 합쳐 tanh를 통과시키면 새 은닉 상태 ht가 나오고, 이것이 다음 시점으로 전달되는 동시에 출력 yt를 만든다.

fig 5-1 · 동일한 셀 A가 시간축을 따라 반복된다 — h가 왼쪽에서 오른쪽으로 흐르며 과거를 전달한다

중요한 오해 하나를 짚자. 그림에 셀이 세 개 그려져 있지만 이것은 서로 다른 세 셀이 아니라 같은 셀 하나를 시간에 따라 펼쳐 그린 것이다. 파라미터는 Wh, Wx 한 벌뿐이고 모든 시점이 이를 공유한다(가중치 공유). 덕분에 임의 길이의 시퀀스를 같은 파라미터로 처리할 수 있다.

수식으로 보는 RNN

$$ h_t = \tanh\!\big(W_h \cdot h_{t-1} + W_x \cdot x_t\big) $$
  • Wx · xt — 현재 입력을 은닉 공간으로 변환.
  • Wh · ht−1 — 직전까지의 요약(기억)을 은닉 공간으로 변환.
  • 더한 뒤 tanh — 둘을 합쳐 −1~1로 눌러 새 은닉 상태를 만든다. tanh는 비선형성을 주고 값이 발산하지 않게 잡아 준다.

Next Token Prediction — 모든 생성의 공통 출력

은닉 상태 ht가 나오면, 여기에 출력 가중치를 곱하고 softmax를 씌워 vocab 전체에 대한 확률 분포를 만든다. 이것이 다음 토큰 예측의 최종 형태다.

$$ \hat{y} = P(w_t \mid \text{context}) = \mathrm{softmax}(Wx + b) $$

흐름은 세 단계다: 모델이 Logits(정규화 안 된 점수 벡터)를 내면 → Softmax가 이를 확률로 바꾸고 → Probability Distribution(vocab 위의 확률 분포)이 완성된다. RNN이든 Transformer든, 요약이든 번역이든 — 모든 생성은 결국 vocab 위의 확률 분포를 예측하는 문제로 귀결된다.

fig 5-2 · Logits → Softmax → Probability Distribution

확률은 실제 softmax 계산이다: pᵢ = exp(zᵢ/τ) / Σ exp(zⱼ/τ). τ가 낮으면 분포가 뾰족해져(greedy에 가까움) 늘 최고 logit만 뽑고, τ가 높으면 평평해져 다양성이 커진다 — 생성의 창의성/안정성 트레이드오프의 핵심 손잡이다.
⚠ RNN의 한계 — 장기 의존성

RNN은 과거를 h 하나에 눌러 담아 전달한다. 그런데 시퀀스가 길어지면 앞쪽 정보가 tanh를 반복 통과하며 희미해지거나(기울기 소실) 폭발한다. "그 사람은 … (30단어) … 이었다/였다" 같은 먼 거리 일치를 잡기 어렵다. 이 문제를 게이트로 정면 돌파한 것이 다음의 LSTM이다.

■ 핵심 정리
  • RNN은 하나의 셀을 시간축으로 반복하며 h로 과거를 전달한다 (가중치 공유).
  • 핵심 수식: hₜ = tanh(Wₕ·hₜ₋₁ + Wₓ·xₜ).
  • 출력은 Logits → Softmax → 확률 분포 — 모든 생성의 공통 형태.
  • 긴 시퀀스에서 장기 의존성(기울기 소실)이 근본 한계다.
06

LSTM — 장기 기억의 도입

0629 · slide 27–30

LSTM(Long Short-Term Memory)은 RNN의 장기 의존성 문제를 해결하기 위해 두 개의 상태와 세 개의 게이트를 도입한다. 이름 그대로 "긴 단기 기억" — 짧은 기억(hidden state)에 더해, 정보를 오래 실어 나르는 별도의 고속도로(cell state)를 얹은 구조다.

두 개의 상태 — 장기 기억과 단기 기억

word vector$x_t$
cell state$c_{t-1}$ — 장기 기억. 시퀀스를 관통하는 정보의 고속도로.
hidden state$h_{t-1}$ — 단기 기억. 현재 시점의 출력이자 게이트 계산의 입력.

cell state는 장기 기억, hidden state는 단기 기억이다. 그리고 세 개의 게이트가 "지금 이 순간의 입력(단기 상황)"을 보고 장기 기억을 얼마나 지울지·채울지·꺼낼지를 결정한다. 즉 각 제어(gate)는 단기 기억의 영향을 받는다.

fig 6-1 · LSTM 셀 — 위쪽 붉은 선(cell state)은 게이트로만 조금씩 수정되며 멀리까지 정보를 나른다

세 게이트 + 후보 — 수식으로 보는 LSTM

forget gate$f_t = \sigma(W_f[h_{t-1}, x_t] + b_f)$
input gate$i_t = \sigma(W_i[h_{t-1}, x_t] + b_i)$
후보 cell$\tilde{C}_t = \tanh(W_C[h_{t-1}, x_t] + b_C)$
최종 cell$C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t$
output gate$o_t = \sigma(W_o[h_{t-1}, x_t] + b_o)$
hidden state$h_t = o_t \odot \tanh(C_t)$

각 게이트는 σ(시그모이드)를 써서 0~1 사이의 "밸브 개폐율"을 낸다. 이 값을 원소별 곱(⊙)으로 적용하면 "얼마나 통과시킬지"가 정해진다.

구성요소역할직관
forget gate fₜ과거 cell state를 얼마나 지울지"이전 주어 정보는 이제 필요 없다" → 0에 가깝게
input gate iₜ새 후보를 얼마나 받아들일지"새 주어가 등장했다" → 1에 가깝게 열어 저장
후보 C̃ₜ이번에 저장할 새 정보 후보현재 입력에서 뽑아낸 기억 재료 (tanh)
최종 cell Cₜ지운 과거 + 받은 새 정보 = 갱신된 장기 기억fₜ⊙Cₜ₋₁ + iₜ⊙C̃ₜ
output gate oₜ장기 기억 중 지금 꺼내 쓸 부분"현재 출력에 필요한 만큼만" 노출
hidden hₜoutput gate로 걸러낸 현재 출력oₜ⊙tanh(Cₜ)
⬤ 왜 게이트가 장기 의존성을 해결하나

핵심은 최종 cell 식 Cₜ = fₜ⊙Cₜ₋₁ + iₜ⊙C̃ₜ의 덧셈 구조다. RNN은 매 시점 tanh 곱셈으로 기억이 지수적으로 희미해졌지만, LSTM의 cell state는 forget gate가 열려 있는 한(fₜ≈1) 과거 정보가 곱셈 감쇠 없이 덧셈으로 이월된다. 정보의 고속도로가 뚫려 있어 기울기가 멀리까지 살아남는다. GRU는 이 아이디어를 게이트 2개로 단순화한 사촌이다(7장).

■ 핵심 정리
  • LSTM은 cell state(장기 기억) + hidden state(단기 기억) 두 상태를 쓴다.
  • 세 게이트 forget · input · output이 σ로 0~1 밸브를 만들어 기억을 제어한다.
  • 최종 cell의 덧셈 갱신 덕분에 정보가 곱셈 감쇠 없이 멀리 이월 → 장기 의존성 해결.
  • 모든 게이트는 단기 기억(hₜ₋₁)의 영향을 받아 열리고 닫힌다.

08

출력층 설계 — 왜 MLP인가

0630 · slide 3–5

CNN이든 RNN이든 Transformer든, 백본(backbone) 뒤에 붙는 출력층(head)은 거의 항상 MLP(다층 퍼셉트론)다. CNN이 이미지를 압축해 마지막에 fc6·fc7·fc8 같은 완전연결층으로 클래스 확률을 내고, RNN이 ht를 뽑아 선형층으로 다음 토큰 분포를 내는 것 — 모두 같은 패턴이다. 왜 그럴까?

Representation vs Decision

딥러닝 모델은 두 부분으로 나뉜다. 백본은 입력을 좋은 표현(representation) 벡터로 바꾸는 일을 하고, 출력층은 그 벡터로부터 결정(decision) 값을 뽑는 일을 한다.

  • 대부분의 task는 결국 "벡터 → 값"의 문제다. 표현이 잘 만들어졌다면, 그 벡터를 라벨/실수로 사상하는 마지막 단계는 단순한 선형 변환(+비선형)이면 충분하다.
  • 표현 공간에서 이미 선형 분리되도록 학습된다. 백본이 열심히 표현을 학습하는 이유가 바로 이것 — 마지막에 선형 경계로 나눌 수 있는 공간을 만들어 두면 출력층은 가벼워도 된다.
  • 일반화 성능과 안정성. 단순한 출력층은 과적합 위험이 작고 학습이 안정적이다.
  • 확률 해석과 loss 함수. 선형층 + softmax 조합은 출력을 확률로 해석할 수 있게 하고, cross-entropy 같은 확률 기반 손실과 수학적으로 잘 맞물린다.
⬤ 한 줄 요약

백본이 "분리 가능한 표현"을 만드는 어려운 일을 하고, 출력층은 "선형으로 자르기"라는 쉬운 일만 한다. 그래서 출력층은 복잡할 필요가 없고, 단순한 MLP가 표준이 된다.

출력층이 MLP가 아닌 경우

물론 "벡터 → 단일 값"이라는 틀을 벗어나는 task도 있다. 이럴 때는 출력 설계 자체가 달라진다.

예외 1Metric Learning

단일 라벨이 아니라 샘플 간 거리를 학습한다. Triplet loss로 "같은 것은 가깝게, 다른 것은 멀게" 임베딩을 배치 — 출력이 값이 아니라 거리 구조다.

예외 2Diffusion

이미지 생성 모델. 출력이 클래스가 아니라 제거해야 할 노이즈(noise prediction) 그 자체다 — 입력과 같은 차원의 텐서를 낸다.

예외 3Reinforcement Learning

강화학습은 보통 정책(policy) + 가치(value) 두 갈래 출력(head)을 동시에 낸다. 단일 head로는 표현되지 않는다.

예외 4Multi-modal Alignment

이미지·텍스트를 같은 공간에 맞추는 정렬 task. 모달리티별 여러 projection head로 서로 다른 입력을 공통 임베딩으로 사상한다.

■ 핵심 정리
  • 모델 = 백본(표현 생성) + 출력층(결정). 대부분 task는 "벡터 → 값" 문제.
  • 백본이 선형 분리 가능한 표현을 만들어 두므로 출력층은 단순한 MLP로 충분하다.
  • 단순 출력층은 일반화·안정성·확률 해석·loss 정합성에서 유리하다.
  • 예외: Metric Learning · Diffusion · RL · Multi-modal은 출력 형태 자체가 다르다.
09

손실 함수와 Surrogate Loss

0630 · slide 6–10

손실 함수(loss function)는 모델이 예측한 값과 실제 값의 차이를 하나의 수치로 표현한 함수다. 이 수치가 작을수록 좋은 예측이다. 학습이란 결국 이 손실을 최소화하는 일이고(11장), 그러려면 손실이 미분 가능해야 한다 — 방향을 알아야 내려갈 수 있기 때문이다.

두 가지 기본 손실

RegressionMSE

연속 값 예측의 표준. 예측과 정답의 제곱 오차 평균. 큰 오차에 더 크게 벌점을 준다.

$\text{MSE}=\frac{1}{n}\sum (y_i-\hat{y}_i)^2$
ClassificationCross-Entropy

분류의 표준. 정답 클래스에 배정한 확률의 −log. 정답을 확신하면 손실 0, 틀리게 확신하면 손실 폭증.

$\text{CE}=-\sum y_i \log \hat{y}_i$
⚠ 반복 확인된 함정 — softmax 이중 적용

PyTorch의 nn.CrossEntropyLoss는 내부에 softmax를 이미 포함한다(정확히는 LogSoftmax + NLLLoss). 그래서 이 손실에는 softmax를 거치지 않은 raw logits를 그대로 넣어야 한다. 모델 출력에 F.softmax를 씌운 뒤 이 손실에 넣으면 softmax가 두 번 적용돼 그래디언트가 뭉개지고 학습이 느려진다 — 노트북 전반에서 계속 강조돼 온 바로 그 실수다.

INTERACTIVE Cross-Entropy — 확신과 벌점의 관계 widget 03

3-클래스 분류에서 정답은 클래스 A다. 모델이 세 클래스에 부여한 logit을 조절하면, softmax 확률과 cross-entropy 손실이 어떻게 변하는지 보인다. 정답 A에 확신할수록 손실이 0으로, 엉뚱한 곳에 확신할수록 손실이 치솟는다.

손실 곡선 — 정답 A에 배정한 확률 p(A) vs 손실 −log p(A)
손실은 실제 계산이다: CE = −log p(정답). p(정답)이 1에 가까우면 손실 → 0, 0에 가까우면 손실 → ∞. 이 가파른 페널티가 모델을 "정답에 확신하도록" 밀어붙인다.

우리가 정말 풀고 싶은 문제 — 그런데 미분이 안 된다

여기서 미묘하지만 중요한 간극이 드러난다. 우리가 실제로 원하는 목표와 학습에 쓸 수 있는 손실이 다르다는 것이다.

task우리가 정말 원하는 것문제
ClassificationAccuracy 최대화정확도는 계단 함수 — 미분 불가
Machine Translation정확한 문장 생성"좋은 번역" 자체가 미분 가능한 수식이 아님
RetrievalRanking 품질순위 정렬은 이산적 — 미분 불가

세 목표 모두 대부분 미분 불가능하다. 미분이 안 되면 Gradient Descent를 쓸 수 없다. 그래서 Surrogate Loss(대리 손실)를 도입한다 — 진짜 목표를 직접 최적화하는 대신, 그와 상관관계가 높으면서 미분 가능한 대리 함수를 최소화한다.

◆ Surrogate Loss의 예

Accuracy(미분 불가)를 직접 못 올리니, 대신 Cross-Entropy(미분 가능)를 내린다. "정답 확률을 높이면 대개 정확도도 오른다"는 상관을 믿고 우회하는 것이다. Cross-Entropy는 그 자체가 목표가 아니라 Accuracy를 위한 대리자다.

Surrogate Loss의 한계 — 목표와의 괴리

대리자는 학습에는 유리하지만, 진짜 목표와 완벽히 일치하지는 않는다. 이 괴리가 실제 문제를 일으킨다.

괴리 1Classification

Accuracy는 decision boundary만 중요하다 — 정답 쪽으로 넘기만 하면 된다. 그런데 Cross-Entropy는 확률 분포 전체를 맞추려 한다. 이미 맞힌 샘플의 확률을 0.9→0.99로 올리는 데도 손실을 쓴다. 정확도에는 무의미한 노력일 수 있다.

괴리 2Next Token Prediction

token 단위로는 잘 맞춰도 전체 문장이 어색할 수 있다. 손실은 매 토큰의 국소 확률만 보지, "문장이 자연스러운가"라는 전역 품질은 보지 않는다. 각 단어는 그럴듯한데 이어 놓으면 이상한 문장 — 2장에서 본 "그럴듯함" 문제의 학습적 뿌리다.

⬤ 그래서 loss와 metric을 분리한다

손실만 보고 있으면 "손실은 내려가는데 실제 성능은 그대로"인 상황을 놓친다. 그래서 학습용 손실(loss)과 평가용 지표(metric)를 분리해서 봐야 한다. 이것이 바로 다음 섹션의 주제다.

■ 핵심 정리
  • 손실 함수 = 예측과 정답의 차이를 미분 가능한 하나의 수치로. Regression은 MSE, Classification은 Cross-Entropy.
  • nn.CrossEntropyLoss는 softmax를 내장 — raw logits를 넣어야 한다 (이중 적용 금지).
  • 우리가 원하는 목표(Accuracy·번역 품질·Ranking)는 대개 미분 불가 → Surrogate Loss로 우회.
  • 대리 손실은 목표와 완벽히 일치하지 않는다 → loss와 metric을 분리해 봐야 한다.

평가지표 (Metric)

0630 · slide 11–20

앞 섹션의 결론을 한 줄로 못 박으면: loss는 학습용, metric은 평가용이다. 둘은 요구 조건부터 다르다.

loss핵심 요건: 미분 가능

Gradient Descent로 최적화해야 하므로 매끄럽고 미분 가능해야 한다. 실제 성능과 다소 어긋나도 감수한다.

metric핵심 요건: 실제 성능 반영

사람이 원하는 성능을 정직하게 측정하면 된다. 미분 가능할 필요가 없어 계단 함수·순위 지표도 자유롭게 쓴다.

Classification Metric

가장 기본이면서 오해가 잦은 영역이다. Accuracy(정확도)는 직관적이지만 클래스 불균형에 취약하다 — 99%가 정상인 데이터에서 "무조건 정상"이라 답해도 정확도 99%가 나온다. 그래서 Precision·Recall·F1이 필요하다.

Regression Metric

  • MAE / MSE / RMSE — 오차의 크기를 재는 세 방식. MAE는 절대 오차 평균(이상치에 둔감), MSE는 제곱 오차 평균(이상치에 민감), RMSE는 MSE의 제곱근(단위가 원래 값과 같아 해석이 쉬움).
  • R²(결정계수) — 모델이 데이터의 분산을 얼마나 설명하는지. 1에 가까울수록 좋고, 0이면 "평균으로 찍기"와 동급, 음수면 그보다 못하다.

Ranking / Retrieval Metric

검색·추천처럼 순위가 중요한 task의 지표다. "정답을 얼마나 위에 놓았는가"를 잰다.

  • MRR(Mean Reciprocal Rank) — 첫 정답이 몇 번째에 나오는지의 역수 평균. 정답이 1위면 1, 2위면 1/2. 첫 정답 위치에 민감.
  • NDCG — 순위에 따라 가중치를 주되, 관련도 등급까지 반영하는 정교한 랭킹 지표.
  • Recall@K — 상위 K개 안에 정답이 몇 개나 들어왔는가. "Top-10 안에 원하는 것이 있나"를 잰다.

이미지 task Metric

  • IoU(Intersection over Union) — 예측 영역과 정답 영역의 겹침 비율. 객체 탐지·분할의 기본 척도.
  • mAP(mean Average Precision) — 여러 클래스·여러 임계값에 걸친 Precision을 종합한, 객체 탐지의 표준 지표.

NLG Metric — 답이 여러 개인 세계

생성(NLG) 평가가 특히 어려운 이유는 정답이 하나가 아니기 때문이다. "고맙습니다"와 "감사해요"는 둘 다 옳은 번역이다. 그래서 exact match(정확히 일치)보다 의미 유사성이 중요하다.

  • BLEU — 생성문과 참조문의 n-gram 겹침을 재는 번역 표준 지표. 정밀도 계열.
  • ROUGE — 요약에서 주로 쓰는 n-gram 겹침 지표. 재현율 계열.
◆ BLEU·ROUGE의 한계

둘 다 표면적 단어 겹침에 기반하므로, 단어는 다르지만 의미가 같은 좋은 문장을 낮게 평가할 수 있다. 이 한계가 LLM 시대에 새로운 평가 방식을 부른다.

LLM에서의 Metric

LLM의 출력은 길고 개방적이라 자동 지표만으로는 부족하다. 그래서 여러 층위의 평가를 조합한다.

방법 1Human Evaluation

사람이 직접 응답 품질을 평가한다. 가장 신뢰도 높지만 느리고 비싸다.

방법 2LLM-as-a-judge

강력한 LLM에게 채점을 맡긴다. 사람 평가를 확장·자동화하지만 심판 모델의 편향이 스며들 수 있다.

방법 3Preference Modeling

"A와 B 중 무엇이 더 나은가"라는 선호 비교를 학습·측정한다. RLHF의 보상 모델과 직결된다.

방법 4Embedding-based

생성문과 참조문을 임베딩 벡터로 바꿔 의미 유사도를 측정한다(예: BERTScore). 단어가 달라도 의미가 가까우면 높게 준다.

Benchmark — 표준화된 시험지

개별 metric을 넘어, 모델의 일반 능력을 비교하려면 벤치마크가 필요하다. 벤치마크가 하는 일은 넷이다: 문제 정의(무엇을 평가할지 규정) · 표준화된 평가 기준(모두 같은 잣대) · 모델 간 비교(공정한 리더보드) · 간접적인 일반 능력 측정(특정 시험 점수로 전반 능력을 추정). 다만 벤치마크는 어디까지나 간접 측정이라, 벤치마크에 과적합된 모델이 실사용에서 실망을 주기도 한다.

■ 핵심 정리
  • loss는 학습용(미분 가능이 요건), metric은 평가용(실제 성능 반영이 요건) — 요구 조건이 다르다.
  • Accuracy는 불균형에 약함 → Precision(오탐 억제) / Recall(누락 억제) / F1을 상황에 맞게.
  • task별 전용 지표: Regression(MAE·RMSE·R²), Ranking(MRR·NDCG·Recall@K), 이미지(IoU·mAP).
  • NLG는 정답이 여럿 → 의미 유사성 중심(BLEU·ROUGE·임베딩), LLM은 Human·LLM-judge·선호·임베딩 조합.
  • Benchmark는 표준화된 비교의 장이지만 일반 능력의 간접 측정임을 잊지 말 것.

Gradient Descent

0630 · slide 21–24

7장 학습 루프의 4·5단계 — "기울기 계산 → 가중치 갱신" — 의 정체가 Gradient Descent(경사하강법)다. 손실 함수라는 지형에서 가장 낮은 골짜기를 찾아 내려가는 방법이다.

모델 학습이란 — 손실을 최소화하는 θ 찾기

학습을 한 문장으로 정의하면 이렇다: loss function을 최소화하는 파라미터 θ를 찾는 문제. 수식으로는

$$ \theta^{*} = \arg\min_{\theta} L(\theta) $$

여기서 θ는 모델의 모든 가중치를 뭉뚱그린 것이고, L(θ)는 그 가중치로 계산한 손실이다. 우리가 원하는 것은 손실을 가장 작게 만드는 θ*다. 문제는 θ가 수백만~수십억 차원이라 수식으로 한 번에 풀 수 없다는 것 — 그래서 조금씩 내려가는 반복법을 쓴다.

Gradient Descent — 손실이 줄어드는 방향으로 조금씩

기울기(gradient) ∇L은 손실이 가장 가파르게 증가하는 방향을 가리킨다. 우리는 손실을 줄이고 싶으니 그 반대 방향으로 조금씩 이동한다.

$$ \theta_{t+1} = \theta_{t} - \eta \, \nabla_{\theta} L(\theta_{t}) $$
  • ∇θL(θt) — 현재 위치에서 손실이 가장 커지는 방향(오르막).
  • − (마이너스) — 그 반대인 내리막으로 방향을 뒤집는다.
  • η (learning rate, 학습률) — 한 걸음의 크기. 너무 크면 골짜기를 건너뛰어 발산하고, 너무 작으면 수렴이 한없이 느리다.
INTERACTIVE Gradient Descent — 학습률이 전부다 widget 05

손실 지형 L(θ)=θ⁴/4 − θ²·1.2 + θ·0.3 위에서 공을 굴려 보자. 학습률 η와 시작점을 바꾸며 실행하면, 매 스텝 θ ← θ − η·∇L이 실제로 계산되어 공이 이동한다. η가 작으면 느리게, 크면 튀거나 발산한다.

공의 이동은 실제 미분 ∇L = θ³ − 2.4θ + 0.3으로 계산된다. 이 지형에는 골짜기가 둘 — 시작점에 따라 다른 곳에 수렴하는 것이 곧 local minimum 문제다. η를 0.6 이상으로 키우면 갱신이 튀며 발산하는 것도 볼 수 있다.

GD 대신 SGD를 쓰는 이유

위 수식의 ∇L을 정확히 계산하려면 전체 데이터셋에 대한 손실을 매 스텝 계산해야 한다(Batch Gradient Descent). 데이터가 수백만 건이면 한 걸음 떼는 데만 엄청난 비용이 든다. 그래서 실무는 SGD(Stochastic Gradient Descent) — 매 스텝 미니배치(일부 샘플)로 기울기를 근사하는 방식 — 를 쓴다. 7장 학습 루프가 "배치 호출"로 시작했던 이유가 바로 이것이다.

이유 1계산 효율

전체가 아닌 일부만 보므로 한 스텝이 훨씬 빠르다. 같은 시간에 더 많이 갱신할 수 있다.

이유 2메모리 절약

전체 데이터를 한 번에 올릴 필요가 없어 큰 데이터셋도 처리 가능하다.

이유 3안장점에 강건

미니배치의 노이즈가 오히려 도움이 된다 — local minimum이나 saddle point에 갇혔을 때 흔들림이 빠져나갈 힘을 준다.

⬤ 두 강의를 잇는 마지막 매듭

이제 전체 그림이 닫힌다. Part 1: 문장이 토큰→ID→벡터로 변환되어 모델(RNN/LSTM)을 통과하고, 출력은 vocab 위 확률 분포(Next Token Prediction)가 된다. Part 2: 그 예측과 정답의 차이를 손실로 재고(미분 가능한 Surrogate), SGD로 θ를 갱신하며, 진짜 성능은 별도의 metric으로 평가한다. "언어 → 텐서 → 학습 → 평가"라는 딥러닝 NLP의 한 사이클이 여기서 완성된다.

■ 핵심 정리
  • 학습 = 손실을 최소화하는 θ 찾기: θ* = argmin L(θ).
  • Gradient Descent: 기울기 반대 방향으로 θ ← θ − η∇L. 학습률 η가 수렴/발산을 좌우.
  • 손실 지형의 골짜기가 여럿이면 시작점에 따라 다른 곳에 수렴(local minimum).
  • 전체 대신 미니배치로 근사하는 SGD: 계산 효율·메모리 절약·안장점 강건성.
