# C 트랙 북마크

읽는 순서: **C1 → C4 → C5 → C2 → C3** (C6 RAG 전용 평가는 D트랙 이후)

## C1. IR 메트릭 — hit@k와 MRR
`eval.py`의 `hit@1`·`hit@3`이 무엇을 세는지. hit@3이 1차 지표인 건 생성 컨텍스트가 상위
3청크라서고, 컨텍스트 크기가 바뀌면 지표도 흔들린다. A7 리랭커가 hit@1만 움직인 것
(0.567→0.707)은 리랭커의 한계가 아니라 hit@3의 사각지대다. `FACET_BOOST` +0.008의 판정은
C3에서.

## C4. 데이터 누수 — 자기참조 평가셋
52문항 병합셋의 자기참조 46건이 만든 착시. 자연어화 때 BM25 단독이 크게 무너진 것
(0.90→0.73)은 성능 저하가 아니라 부풀림 제거다. 부풀림이 검색기마다 달라서, 자기참조 셋
위에서 정한 하이브리드 가중·부스트 값은 전부 재검토 대상이다.

## C5. 평가셋 라벨링 방법론
gt 8건 교정과 팀 라벨 병합이 점수에 남긴 것. 오류율 8/52면 시스템 간 격차가 15% 압축돼
개선 감지가 둔해진다. 병합 규칙(union/다수결)에 따라 `hit@3`이 세는 것 자체가 달라지므로
어느 규칙이었는지 기록 확인이 먼저다. 교정 후 점수 상승은 개선이 아니라 측정 오류 제거다.

## C2. micro 평균과 macro 평균
`h3_macro`가 전체 `hit@3` 옆에 따로 있는 이유. 착오송금 0.889는 micro 0.945 안에서 보이지
않고, micro만 보면 이미 잘하는 업무를 더 고치라는 신호가 나간다. 문항 배분이 다른 락끼리의
micro 비교는 배분 차이만큼 오염이다.

## C3. 표본 크기와 신뢰구간
400문항 셋의 해상도는 2~3%p. `FACET_BOOST` 0.945→0.953은 net 3문항이라 어떤 분해로도 유의
불가이고, 역전 없이 net +6부터 유의하다. 300→400 확장은 SE 13% 감소에 그쳤다. 지금 셋에서
오차를 줄이는 가장 싼 손잡이는 문항 추가가 아니라 라벨 정제다.
